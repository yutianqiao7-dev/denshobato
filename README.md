# 伝書鳩

**→ https://yutianqiao7-dev.github.io/denshobato/**

鳩を飼って、人に渡して、返ってくるのを待つメッセージアプリ。

[ギズモード・ジャパンの記事](https://www.gizmodo.jp/article/there-are-carrier-pigeon-apps-now-because-pigeon-technology-is-actually-superior/)で紹介されていた「Carrier Pidge」を下敷きに、本物の伝書鳩の仕組みに寄せています。

## 鳩は自分の鳩舎にしか帰らない

これがすべての土台です。伝書鳩は「相手の家へ配達する」鳥ではなく、「どこで放たれても自分の家へ帰る」鳥です。だから：

- **手紙を送るには、相手の鳩を預かっておく必要があります。** その鳩を放つと、相手の鳩舎へ帰り、手紙が届きます。
- **手紙を受け取るには、自分の鳩を相手に渡しておく必要があります。** 相手がその鳩を放つと、手紙を持ってあなたの鳩舎へ帰ってきます。

つまり文通を始めるには、まず二人で鳩を交換します。鳩は一度放てば飼い主のもとに残るので、続けるにはまた渡し合うことになります。

飛行時間は二つの鳩舎の距離ぶん。巡航速度は 80 km/h（本物と同じくらい）が既定値です。

- 東京 ↔ 大阪 … 約 403 km / およそ 5 時間
- 東京 ↔ パリ … 約 9,716 km / およそ 5 日

## 鳩舎

「鳩舎」の画面は、実物の鳩舎と同じ**合板の巣箱が並んだ壁**です。5 列 2 段で **10 個**。手元に置ける鳩はこの 10 羽まで。埋まっているあいだは新しい鳩を迎えることも、人の鳩を預かることもできません。誰かに渡すか、放つと空きます。

鳩は絵文字ではなく一羽ずつ描いてあります。カワラバトの体つき（白い鼻瘤、橙色の虹彩、二本の翼帯、首の緑と紫の光沢、赤い脚）で、羽色は青・斑・白・赤・黒・淡の 6 種。迎えた時点で決まり、鳩コードで相手の端末に渡っても同じ色のままです。

- それぞれ勝手な間合いで体を揺らします
- 元気な鳩はときどき跳ね、ときどき翼を伸ばします
- 腹が減ると動きが鈍り、弱ると羽をふくらませてうずくまります（脚も見えなくなります）
- 鳩舎の前を横切っていくのは、いま飛んでいる鳩。翼を上下に打ちます

**餌のやり方は二通りあります。** 器を押すと餌を手に持った状態になり、あとは鳩をつつくだけで食べます（続けて何羽でも）。器をもう一度押すと置きます。器をつまんで鳩まで運ぶドラッグも使えます。どちらでも、落とした鳩の足元に餌がこぼれ、その鳩の腹の減り具合だけが戻ります。

餌を持っているあいだは、腹の減った鳩が光ってどれにやればいいか分かります。

**自分の鳩と預かった鳩は見分けがつきます。** 預かった鳩には足環が付いていて、その巣箱には飼い主の名札が掛かります。足環と名札の色は飼い主ごとに決まるので、二人から預かっていても取り違えません。一覧も「自分の鳩」と「預かっている鳩」に分かれています。

鳩をつつくと、その一羽の受け渡し・手紙を持たせる操作が開きます。

**鳩は消せます。** 一覧のどのカードにも、小屋の鳩をつついたときにも「消す」があります。消すと何が起きるかは鳩の居場所で違うので、確認のときに書き分けています（預けている鳩を消しても、その鳩が持って帰る手紙は届きます。ただし鳩は鳩舎に戻りません）。

## 鳩は卵からしか増えない

**新しい鳩を好きなだけ呼べる仕組みはありません。** 増やすには、元気な成鳥を二羽つがいにして、卵から育てます。

| | かかる時間 | できること |
| --- | --- | --- |
| 卵 | 24時間で孵る | 餌は要らない。巣箱をひとつ占める |
| 雛 | さらに24時間で巣立つ | 餌が要る。飛べない・渡せない |
| 成鳥 | — | 手紙を運べる。渡せる。親になれる |

- 羽色は**親のどちらかを継ぎます**。1割の確率で先祖返りして別の色が出ます
- 一覧には「◯◯と△△の子」と血筋が残ります
- 親になった鳩は **5日間**、次の卵を持てません
- 卵と雛も巣箱をふさぐので、10個の枠を取り合います

つまり一羽の重みが変わります。餓死させれば減り、遠くへ放って帰らなければ減り、人に渡せば減る。取り返すには二日かかります。

**つがいを組める鳩がいなくなったとき（自分の鳩が二羽未満）だけ**、野良鳩が一羽迷い込んできます。詰まないための逃げ道で、ふだんは出ません。はじめるときも二羽から始まります。

## 鳩は世話をしないと死ぬ

手元にいる鳩は、自分の鳩も預かった鳩も、あなたが餌をやります。鳩舎の下の器から餌をつまんで、鳩の上で離してください。

| 満腹ゲージ | 状態 | 影響 |
| --- | --- | --- |
| 満 〜 3/4（餌から24時間） | 元気 | — |
| 3/4 〜 1/2（〜48時間） | おなかを空かせている | 少し遅くなる・帰り着かない確率が 1.6 倍 |
| 1/2 〜 空（〜96時間） | 弱っている | かなり遅くなる・帰り着かない確率が 2.5 倍 |
| 空（96時間） | 死んでしまう | もう放てません |

鳩の状態は文字ではなく**満腹ゲージ**で出ます。餌をやると満ちて、放っておくと 4 日かけて空になります。ゲージには目盛りが二本入っていて、そこを割ると「空腹」「衰弱」に変わります。鳩舎の巣箱の縁にも一羽ずつ細いゲージが出るので、どの鳩が減っているかは絵を見れば分かります。

預けている鳩と空を飛んでいる鳩は、あなたの世話の対象外です（預けた鳩の世話は相手の仕事）。帰ってきた鳩は腹を空かせた状態で鳩舎に入ります。

### 預けた鳩が、相手の手元で死んだら

預かった鳩を飢えさせてしまったら、そのことは飼い主に伝わります。

- 中継所を使っていて、その鳩を QR で受け取っていれば、**訃報は自動で飼い主の巣穴に置かれます**。飼い主の側では鳩が「死んでしまいました」に変わり、次にアプリを開いたときに知らせが出ます（通知を許していれば通知も届きます）
- 中継所を通っていない鳩は自動では伝わりません。鳩舎の「もういない鳩」に**「訃報を伝える」**が出るので、QR かコードを飼い主に読んでもらってください
- 飼い主の側には「誰の手元で死んだか」が残ります。責任の所在は曖昧にしません

## 鳩は夜に休み、天気に足止めされる

鳩は昼のあいだしか飛びません。**朝 5 時から日暮れの 19 時まで**が飛行時間で、夜は止まり木で休みます。その日のうちに着かない距離なら、鳩は途中で一泊して、翌朝またつづきを飛びます。

- 何時が朝かは、**放った鳩舎の経度**から出しています（`src/geo.ts` の `dayBounds`）。時差のある相手とやりとりしても、両方の端末で同じ時刻に日が暮れます
- 「あと◯時間」は夜のぶんを含んだ実時間です。夕方に放つと、残り 5 時間の鳩でも着くのは翌朝になります
- 空の画面と手紙の画面には、いま飛んでいるのか休んでいるのかが出ます

放った瞬間に、その旅の空模様もひとつ決まります。

| 空模様 | 出やすさ | 飛ぶ時間 |
| --- | --- | --- |
| 晴れ | 58% | そのまま |
| 追い風 | 8% | 15% 速い |
| 向かい風 | 14% | 35% 遅い |
| 雨 | 13% | 60% 遅い |
| 嵐 | 7% | 2.4 倍 |

空模様は鳩ごと・旅ごとに決まり、途中で変わりません。手紙コードにも入って渡るので、相手の端末でも同じ空を飛びます。

## 鳩は帰ってこないことがある

放った瞬間に、その鳩が無事に着くかどうかは決まっています。あとから確率が転がることはありません。

- 帰らないと決まった鳩は、旅程の 15%〜85% のどこかで消息を絶ちます
- その時刻を過ぎると、手紙は **空** から消えて **文箱 → 戻らなかった** に移ります
- 受け取るはずだった手紙は、本文が永久に開きません。画面にも出しませんし、DOM にも載せません
- 自分が書いた手紙なら文面は手元に残るので、「同じ文面で書き直す」で別の鳩に託せます

確率は距離と鳩の調子で決まります（`src/geo.ts` の `lossChance`）。

```ts
Math.min(0.6, (1 - Math.exp(-km / 40000)) * risk)
```

東京→パリなら、元気な鳩で 5 羽に 1 羽、弱った鳩なら 2 羽に 1 羽が帰り着きません。きつすぎる・ぬるすぎると感じたら `40000` を動かしてください。大きくすると安全になります。

## 鳩舎の場所

町の一覧から選ぶほか、**「いまいる場所にする」**で端末の位置から決められます。座標は丸めずにそのまま使います。

- 座標は Android・iOS・ブラウザのどこでも取れます（`expo-location` の `getCurrentPositionAsync` は web 対応）
- 地名にするのは Android と iOS だけです（`reverseGeocodeAsync` は web 非対応）。ブラウザでは手持ちの町のうち 120km 以内でいちばん近い名前を仮に置き、それより遠ければ「現在地」とします。名前はその場で直せます
- **鳩舎の座標は、鳩を渡すときの QR に入って相手に渡ります。** 帰巣先そのものだからです。丸めていないので、自宅で取れば自宅の座標が相手に渡ります

## 動かす

```bash
npm install
npx expo start
```

スマホに **Expo Go** を入れて、表示された QR を読むと実機で動きます。同じ Wi-Fi につないでおいてください。
ブラウザで確かめるだけなら `npm run web` （http://localhost:8081）。

## 使い方

1. 名前・はじめの一羽の名前・あなたの鳩舎の場所を決める（つがいの相手がもう一羽ついてきます）
2. **設定** で相手を登録する（名前と、相手の鳩舎の場所）
3. **鳩舎** で自分の鳩を「誰かに渡す」。出てきた QR を相手に読んでもらう
4. 相手にも同じことをしてもらい、**鳩舎 → 鳩を預かる** で読み取って預かる
5. 預かった鳩に「手紙を持たせる」と、その鳩は目の前で飛び立って相手の鳩舎へ向かう
6. 中継所があれば、相手は何もしなくても届く。ないときは、飛び立った直後に出る QR を読んでもらう
7. 着いたら **文箱 → 送った** に残る
8. 毎日、鳩舎をのぞいて餌をやる

相手と直接会って鳩を手渡したときは、コードを使わず **鳩舎 → 鳩を預かる** に書き留めるだけでもかまいません。

## 届け方

**鳩を渡すときの QR に、あなたの「巣穴の住所」が入っています。** 32桁の乱数で、この QR でしか渡りません。相手がその鳩を放つと、手紙はあなたの巣穴に置かれ、あなたのアプリが開いたときに自動で拾います。**受け取る側は何もしません。**

中継所は Firebase Realtime Database です（`src/relayConfig.ts` の `RELAY_URL`）。ここを空にすると中継所を使わず、手紙ごとに QR を手渡しする形に自動で切り替わります。渡していない手紙は「空」と一覧に「まだ相手に渡していません」と出続けます。

中継所を通るのは手紙の暗号化されていない本文ではなく、鳩コードと同じ形の文字列ですが、**巣穴の住所を知っている人は読めます**。住所は QR でしか渡らないので、それを知らない人には見つけられません。

### 中継所を立てる

1. [Firebase コンソール](https://console.firebase.google.com/)でプロジェクトを作る
2. 「Realtime Database」を作る（ロケーションはどこでも可）
3. 「ルール」に `firebase-rules.json` の中身を貼って公開する
4. データベースの URL を `src/relayConfig.ts` の `RELAY_URL` に入れる

手紙は `mailboxes/{巣穴の住所}/{手紙のid}` に `{code, at}` の形で置かれます。ルールは「24文字以上の住所の下だけ、読めて、新しく置けて、消せる（上書きはできない）」です。

API キーも SDK も要りません。REST を直接叩いています。

### やりとりの中身

やりとりは三種類の文字列だけで成り立っています。

- **鳩コード**（`DENSHOBATO1H.…`）… 自分の鳩を相手に預ける。鳩の名前と帰巣先が入っています
- **手紙コード**（`DENSHOBATO1.…`）… 放った鳩を飼い主の端末に引き渡す。手紙・到着時刻・空模様・その鳩が力尽きるかどうかまで入っています
- **訃報コード**（`DENSHOBATO1D.…`）… 預かった鳩が死んだことを飼い主に伝える。鳩の id と、看取った人の名前と時刻だけです

**受け渡しは QR が基本です。** 「誰かに渡す」を開くとすぐ QR が出るので、受け取る側は「コードを貼り付ける」を開いてカメラで読むだけ。相手を事前に登録しておく必要はありません。

読み取れたかどうかはアプリからは分からないので、渡した本人が「読んでもらった」を押した時点で鳩が飛び立ちます。そのあとで「誰のところへ？」と一度だけ聞きますが、書き留めなくてもかまいません（鳩舎には「渡したまま」と出ます）。相手が誰であっても、その鳩が持って帰る手紙はあなたの鳩舎に届きます。

離れているときのために、同じ内容を文字で送る道も残してあります（QR に入りきらないほど長い手紙は、文字で送ってください）。

手紙コードは今すぐ渡してかまいません。相手の端末でも同じ時刻まで封は開きませんし、帰らない鳩は相手の側でも帰りません。

**QR は画像からも読めます。** その場にいないときは、相手に QR のスクリーンショットを送ってもらって、写真から読み取れます。カメラを開けない端末でも受け取れます。

Web ではカメラの QR 読み取りが expo-camera で使えないので、ブラウザ用には `getUserMedia` と jsQR による実装（`QrScanner.web.tsx`）を別に置いています。画像からの読み取りは、web が jsQR、実機が `Camera.scanFromURLAsync` です。

## 中身

| ファイル | 役割 |
| --- | --- |
| `src/geo.ts` | 大圏距離（Haversine）、飛行時間、夜の休み、空模様、帰らない確率、残り時間の表示 |
| `src/flock.ts` | 手紙と鳩の「いま」を時刻から導く（世話の状態・飛行中・消息不明） |
| `src/pigeonCode.ts` | 鳩コード・手紙コード・訃報コードの符号化・復号（UTF-8 → Base64、依存なし） |
| `src/store.tsx` | アプリ全体の状態と操作。`reconcile` が経過時間ぶんの帳尻を合わせる |
| `src/notify.ts` | 到着・喪失・世話のローカル通知。使えない環境では黙って無効になる |
| `src/pigeonArt.tsx` | 鳩そのものの絵。羽色 6 種と、止まり姿・飛び姿 |
| `src/components/Loft.tsx` | 巣箱 10 個の鳩舎、餌のドラッグ、鳩の動き |
| `src/components/QrScanner*.tsx` | QR の読み取り（ネイティブ / ブラウザ） |
| `src/relay.ts` | 中継所とのやりとり（Firebase RTDB の REST を直接） |
| `src/flyaway.tsx` | 鳩が飛び去る演出 |
| `src/screens/` | 空 / 文箱 / 鳩舎 / 設定 と、各モーダル |

鳩の生死も飛行中かどうかも、保存された時刻と現在時刻から毎回導いています。アプリを閉じているあいだも時間は進みます。

## 決めごと

- どんなに近くても飛行は最低 5 分。隣の部屋でも鳩には支度が要ります。
- 受け取った手紙は、到着時刻を過ぎるまで本文を画面に出しません。
- 通知は端末のローカル通知だけ。アプリの外にデータは一切出ません。
- 鳩を迎えるのは無料です。元のアプリと違って、ここで課金は求めません。

## この先やるなら

- コードをディープリンク（`denshobato://` や QR）にして貼り付けを省く
- 季節で日の長さを変える（いまは通年 5 時〜19 時）
- 血統書。何代前まで遡れるかを鳩舎から見られるようにする
